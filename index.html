Product Design AI Tooling System

A working, evidence-based model connecting the AI Tooling Landscape Map, the Tool and Capability Register, and the Measurement Dashboard. All example data is clearly labelled - no Skyscanner tools, owners, or results are implied to be confirmed unless stated.

Purpose of this file

This system visualises and manages Skyscanner Product Design's AI tooling ecosystem across three connected artefacts. It does not assume that adopting more tools is the desired outcome - it exists to support decisions to scale, integrate, improve, pilot, consolidate, retire, or investigate capabilities.

Register → Map → Dashboard

Detailed records create the landscape view. The landscape reveals portfolio decisions. The dashboard tests whether those decisions create value.

How the three artefacts relate

  • Capability Register - the detailed, maintainable source-of-truth for every tool or capability.
  • Landscape Map - a shared visual model showing where capabilities sit across the design lifecycle.
  • Measurement Dashboard - evidence of whether capabilities are actually delivering value.

Initial scope

Product Design, with adjacent disciplines included only where they connect directly to Product Design workflows: User Research, Content Design, Product Management, Engineering, Data and experimentation, and Security/Privacy/Legal/Procurement.

How to add or update a capability

Add a new record to the Capability Register using the empty template (see Register tab), assign it to a lifecycle stage and workflow row, and it will appear on the Landscape Map automatically once its lifecycle column and workflow stage are set. Unknown fields must use a labelled placeholder - never a fabricated value.

How to record unknown information

Use placeholders such as Tool to validate, Owner to confirm, Approval status unknown, Baseline required, Target to confirm, No evidence collected, or Data source to identify. Never leave a value that looks confirmed if it has not been verified.
